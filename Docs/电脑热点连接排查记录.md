# 电脑热点连接排查记录

日期：2026-10-23。

## 现象与原因

用户在公司让电脑连接KUKA-Office，再开启与家中相同名称的LEO欢乐屋热点。Windows已看到小车接入，但浏览器仍停留在家里的旧地址 `http://192.0.2.20/`，页面无法连接。

本轮确认：电脑热点地址为192.168.137.1，小车在热点下取得192.168.137.217。小车标识与既有烧录记录一致；新地址HTTP状态返回connected=true、ssid=LEO欢乐屋，WebSocket握手成功；浏览器随后显示用户取得及释放控制权。根因是换网络后DHCP分配地址变化，入口仍使用旧地址。

电脑上游公司网络的企业认证不是本次控制台失联原因。小车连接的是电脑提供的热点，无需直接接入公司网络。

## 修复

- 更新 `firmware/web-device.json` 至新地址，保留只在本地使用的小车网络标识用于定位。
- 双击入口改为运行 `firmware/open_console.ps1`：先验证保存地址，失败时仅查询已有邻居记录中匹配的小车地址，确认状态接口后保存并打开。
- 不进行全网段扫描；已有记录中没有小车时，会提示检查供电及网络并从热点列表查看地址。
- 更新使用说明。固件、Wi-Fi凭据和电机方向未修改，本轮没有发送运动指令。

## 验证

1. 旧地址访问超时，可复现问题。
2. 通过现有热点设备记录定位新地址，HTTP和WebSocket均正常。
3. 将入口缓存临时恢复为旧IP，运行发现逻辑，约6.15秒找到新地址并保存，验证通过。
4. 使用新地址运行同一入口检查，约0.63秒返回，验证通过。
5. 浏览器记录用户取得及释放控制权；最初状态接口显示A/B输出均为0、无控制者。后续主动复查前新地址再次超时，用户已确认当时主动关过小车；该次断开不作为网络异常证据。
6. A反向设置仍为true，B反向与左右交换仍为false。
7. 浏览器已导航到新地址，曾显示Wi-Fi已连接；后续用户确认关机。重新电池上电的A电机自转故障另见《A电机上电自转排查记录》。

证据：`firmware/hotspot-address-regression-20261023.json`。旧地址配置备份：`tmp/web-device-before-hotspot-20261023.json`。

当前状态另报告OLED未检测到。本轮仅处理控制台连接，没有修改屏幕相关代码或接线。

## 再次上电后的页面地址修正

主控后来取得192.168.137.61，但用户浏览器仍停留在192.168.137.217。已验证自动入口返回61，并将当前浏览器直接导航至61。页面曾显示Wi-Fi已连接、屏幕已识别；用户取得控制权并勾选安全确认后，方向及单电机按钮启用。调试助手只做状态查询与握手，没有发运动指令；因用户浏览器已拥有控制权，没有抢占。随后新地址再次不响应，已询问用户是否关机/拔电，或是否在电机动作后掉线，不能把本轮标为稳定控制全部恢复。证据：`firmware/control-address-restored-20261023.json`。
