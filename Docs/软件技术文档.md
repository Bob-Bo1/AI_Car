# AI 桌面小车软件技术文档 V0.1

> 项目：XIAO ESP32-C3 双电机 Wi-Fi 桌面小车  
> 文档状态：软件方案已完成，代码与实机测试未开始  
> 更新日期：2026-09-22  
> 对应硬件基线：《硬件技术文档》V0.1  
> 首版目标：电脑和手机使用同一套网页控制小车，断网自动停车，动作平稳且可以标定。

## 1. 技术路线与范围

### 1.1 软件目标

首版软件完成以下闭环：

1. XIAO ESP32-C3 上电后先让四个电机控制脚保持低电平；
2. 小车连接已保存的 Wi-Fi，连接失败时自动建立自己的热点；
3. 电脑或手机打开小车网页，通过 WebSocket 发送实时控制指令；
4. 固件把“前后速度、左右转向”换算成左右轮目标速度；
5. 电机经过斜坡加减速和换向停顿后执行；
6. 指令中断、网页断开或 Wi-Fi 丢失时，固件在规定时间内停车；
7. OLED、前灯和网页同步显示连接、运动、电量和故障状态；
8. 标定参数保存在主控内部，断电重启后继续有效。

### 1.2 总体结构

```text
电脑/手机浏览器
  ├── HTTP：加载控制页面、读取配置
  └── WebSocket：实时控制、心跳、状态回传
                 │
                 ▼
XIAO ESP32-C3 固件
  ├── 网络与会话管理
  ├── 指令校验与控制权管理
  ├── 差速混控与电机状态机
  ├── GPIO / LEDC PWM / I2C / ADC
  ├── OLED 与 WS2812B 状态提示
  └── NVS 参数保存 + LittleFS 网页文件
```

小车本身提供控制页面和通信服务。电脑端无需常驻程序，手机端无需先开发原生 APP。后续如要加入语音、摄像头或公网控制，再单独设计上位机或云端服务。

### 1.4 Web 与 PWA 的实际边界

首版保证电脑和手机浏览器可以使用同一套响应式页面。网页中可以准备 `manifest.webmanifest`，并支持添加桌面快捷方式。

标准 PWA 的离线缓存依赖 Service Worker，而主流浏览器通常只允许它运行在 HTTPS 或本机地址。ESP32 在局域网中直接提供普通 HTTP 页面时，部分手机不会允许完整 PWA 安装。因此首版验收以“浏览器可稳定控制”为准；安装图标属于兼容性增强。若后续必须做到各平台都可安装，需要增加可信 HTTPS 网关或封装为原生 APP，这会单独立项。

### 1.5 首版明确不做

- 公网远程控制、端口映射和云端中继；
- 摄像头视频回传；
- 语音识别、视觉导航、自主避障；
- 精确里程、角度和位置闭环；
- 多人同时驾驶；
- 在线自动升级，首版先用 USB 有线升级。

### 2.2 代码边界

- `main.cpp` 只负责启动顺序和循环调度，不塞入业务细节；
- 电机、网络、安全、电量、屏幕和灯光分别独立；
- 网页只能提交目标动作，不能直接控制 GPIO；
- 任何运动指令都必须经过协议校验、控制权检查和安全模块；
- 引脚只在 `board_pins.h` 定义一次，防止软件和接线表出现两个版本；
- 标定参数集中存放，网页和固件共用同一字段名称。

## 3. 固件关键模块

### 3.1 启动顺序与上电安全

固件启动顺序固定如下：

1. 第一时间把 GPIO4、GPIO5、GPIO21、GPIO20 设置为输出低电平；
2. 初始化串口日志，波特率为 **115200**；
3. 读取 NVS 参数并做范围校验，异常时使用安全默认值；
4. 初始化 I2C、OLED、前灯和电池 ADC；
5. 配置四路 LEDC PWM，但占空比保持 0；
6. 挂载 LittleFS，失败时仍保持电机停止并显示故障；
7. 启动 Wi-Fi、HTTP 和 WebSocket；
8. 进入 `STOPPED`，等待控制端领取控制权。

任何初始化失败都不能让电机产生有效 PWM。看门狗复位后也必须重新执行这套安全启动。

### 3.2 软硬件一致性表

| 功能 | XIAO 引脚 | ESP32-C3 GPIO | 软件模式 | 频率/协议 | 上电默认 |
|---|---:|---:|---|---|---|
| 电池电压 | D1 | GPIO3 / ADC1_CH3 | 模拟输入 | ADC，建议 11dB 衰减 | 只读 |
| 左电机 IN1 | D2 | GPIO4 | LEDC PWM/数字输出 | 20kHz，8bit | 低 |
| 左电机 IN2 | D3 | GPIO5 | LEDC PWM/数字输出 | 20kHz，8bit | 低 |
| OLED SDA | D4 | GPIO6 | I2C | 400kHz 起步；不稳则降至 100kHz | 总线上拉到 3.3V |
| OLED SCL | D5 | GPIO7 | I2C | 地址先扫描 0x3C/0x3D | 总线上拉到 3.3V |
| 右电机 IN3 | D6 | GPIO21 | LEDC PWM/数字输出 | 20kHz，8bit | 低 |
| 右电机 IN4 | D7 | GPIO20 | LEDC PWM/数字输出 | 20kHz，8bit | 低 |
| 两颗前灯数据 | D10 | GPIO10 | 数字输出 | WS2812B 单线协议 | 低/熄灭 |
| 保留 | D0/D8/D9 | GPIO2/8/9 | 不初始化 | 启动配置相关 | 保持未连接 |

ESP32-C3 有 6 路 LEDC 通道，电机占用 4 路，还剩 2 路硬件 PWM 能力，但没有低风险普通物理 GPIO 可随意扩展。电池检测继续保留。

### 3.3 网络管理

#### 3.3.1 启动规则

1. NVS 中存在 Wi-Fi 账号时，先进入 STA 模式连接路由器；
2. 首次等待 15 秒，连接成功后 OLED 显示局域网 IP；
3. 连接失败或没有账号时，启动 SoftAP；
4. SoftAP 名称使用 `AI-Car-XXXX`，`XXXX` 为设备 MAC 后四位；
5. SoftAP 使用 WPA2 密码，密码至少 8 位，正式交付时不得保留公开默认密码；
6. SoftAP 默认地址为 `192.168.4.1`，OLED 同时显示访问地址；
7. STA 运行中掉线后立即停车，后台重连；连续 30 秒未恢复则同时开启 SoftAP 供用户处理。

#### 3.3.2 配网方式

首版提供本地配网页面：

- 用户连接 `AI-Car-XXXX`；
- 浏览器打开 `http://192.168.4.1`；
- 页面扫描并选择 2.4GHz Wi-Fi，输入密码；
- 固件只把账号写入 NVS，不写入网页文件或日志；
- 保存成功后重启并尝试 STA 连接；
- 提供“清除网络配置”按钮，执行前需要二次确认且电机必须停车。

ESP32-C3 只支持 2.4GHz Wi-Fi。页面要明确提示，避免用户选择只有 5GHz 的网络。

#### 3.3.3 访问地址

- SoftAP：固定使用 `http://192.168.4.1`；
- STA：OLED 显示实际 IP，例如 `http://192.168.1.88`；
- 可增加 `ai-car.local` 的 mDNS 名称，但不能把它作为唯一入口，因为部分 Android 手机和路由器解析不稳定。

### 3.4 HTTP 与 WebSocket 服务

| 服务 | 端口 | 用途 | 运动控制权限 |
|---|---:|---|---|
| HTTP | 80 | 页面、静态资源、只读信息、配置 | 不直接驱动电机 |
| WebSocket | 81 | 实时指令、心跳、状态回传 | 经过控制权和安全检查后生效 |
| USB 串口 | 115200 波特 | 调试日志、故障定位 | 发布版不接受任意运动命令 |

WebSocket 地址由页面根据当前主机生成，例如 `ws://192.168.4.1:81/`。服务端每次只接受短文本 JSON，首版单条消息上限设为 512 字节；超长、字段缺失、类型错误或数值越界均拒绝执行。

### 3.5 控制协议 V1

所有消息都含 `v:1` 和 `type`。运动消息还含递增的 `seq`。服务端只按收到消息的本机时间判断是否超时，不相信手机或电脑的时间。

#### 3.5.1 客户端到小车

领取控制权：

```json
{"v":1,"type":"claim","clientId":"phone-a7f2"}
```

连续驾驶：

```json
{"v":1,"type":"drive","seq":104,"throttle":60,"steering":-25,"gear":2}
```

- `throttle`：-100 到 100，正数前进，负数后退；
- `steering`：-100 到 100，正数右转，负数左转；
- `gear`：1、2、3，默认上限建议为 45%、70%、100%，最终受 `maxDuty` 限制；
- 页面按住按钮或摇杆时每 100ms 发送一次；
- 相同 `seq` 重复到达时只确认一次，不重复改变状态；
- 小于或等于已执行序号的旧消息直接丢弃。

立即停车：

```json
{"v":1,"type":"stop","seq":105,"reason":"user"}
```

心跳：

```json
{"v":1,"type":"ping","seq":106}
```

释放控制权：

```json
{"v":1,"type":"release","seq":107}
```

#### 3.5.2 小车到客户端

连接信息：

```json
{"v":1,"type":"hello","deviceId":"AI-Car-A1B2","fw":"0.1.0","control":"free"}
```

状态回传：

```json
{"v":1,"type":"state","owner":"phone-a7f2","motion":"RUNNING","left":42,"right":70,"batteryV":3.78,"battery":"normal","rssi":-54,"fault":null}
```

确认或错误：

```json
{"v":1,"type":"ack","seq":104}
```

```json
{"v":1,"type":"error","seq":104,"code":"CONTROL_BUSY","message":"control owned by another client"}
```

#### 3.5.3 错误码

| 错误码 | 含义 | 小车动作 |
|---|---|---|
| `BAD_JSON` | JSON 无法解析 | 忽略消息 |
| `BAD_FIELD` | 缺字段或数值越界 | 忽略消息 |
| `OLD_SEQ` | 重复或过期序号 | 保持当前动作并回传状态 |
| `CONTROL_BUSY` | 其他客户端正在控制 | 拒绝运动指令 |
| `NO_CONTROL` | 客户端未领取控制权 | 拒绝运动指令 |
| `LOW_BATTERY` | 低电压锁定 | 电机保持停止 |
| `MOTOR_FAULT` | 电机安全状态异常 | 四路输出清零 |
| `FS_ERROR` | 网页文件系统异常 | 电机保持停止，可串口排查 |

### 3.6 控制权、心跳与失控保护

#### 3.6.1 单控制者租约

- 第一台成功发送 `claim` 的客户端成为控制者；
- 其他页面只能查看状态，可以请求接管，但不能直接覆盖；
- 控制者主动释放、WebSocket 断开或租约超时后，先停车，再释放控制权；
- 新控制者必须重新 `claim`，页面不能沿用旧会话；
- 服务端生成会话标识，设备重启后旧标识全部失效。

#### 3.6.2 时间参数

| 项目 | 默认值 | 说明 |
|---|---:|---|
| 页面发送周期 | 100ms | 按住控制时持续发送 |
| 心跳周期 | 200ms | 没有动作变化时仍维持连接 |
| 指令超时 | 500ms | 超时进入 FAILSAFE 并清零输出 |
| 控制权释放 | 停车后 1s | 允许短暂网络抖动，不能继续运动 |
| 状态广播 | 100ms | 网页约 10Hz 刷新 |

网页在 `pointerup`、`pointercancel`、窗口失焦、页面隐藏和离开页面时都发送 `stop`。浏览器事件只能作为第一层保护，500ms 固件超时才是最终保护。

#### 3.6.3 停车等级

- 普通松手：按减速斜坡回到 0；
- 用户急停、掉线、指令超时、低电压或内部故障：四路占空比立即清零并输出 `00`；
- `11` 短路刹车首版默认关闭，只有确认驱动板型号、电流和温升后才允许启用。

### 3.7 差速混控与转向

#### 3.7.1 输入处理

1. `throttle` 和 `steering` 先限制在 -100 到 100；
2. 摇杆中心死区默认 ±5，防止手指轻微抖动；
3. 低速区可使用柔和曲线，提高小幅转向的可控性；
4. 三档速度只改变最大输出，不改变方向逻辑。

#### 3.7.2 左右轮混合

```text
leftRaw  = throttle + steering
rightRaw = throttle - steering
```

若两者绝对值的最大值超过 100，就按同一比例缩小，保留转向比例：

```text
scale = 100 / max(abs(leftRaw), abs(rightRaw))
left  = leftRaw  × scale
right = rightRaw × scale
```

然后应用左右补偿、方向反相和档位上限：

```text
leftTarget  = left  × leftScale  × gearLimit
rightTarget = right × rightScale × gearLimit
```

- `leftScale`、`rightScale` 默认 1.00，可按实车修正；
- 左右电机正反转最低启动值可以分别保存，共四组参数；
- 机械装配导致方向相反时，优先用 `leftInvert/rightInvert` 配置修正，接线确认后锁定。

#### 3.7.3 直行和转向边界

两台电机没有编码器，固件只能控制输出强弱，无法知道车轮真实速度。首版目标是同一地面、相近电量下动作趋势可重复；不承诺精确走直线、精确转 90 度或精确行驶距离。

### 3.8 电机状态机与稳定控制

#### 3.8.1 状态定义

| 状态 | 含义 | 电机输出 |
|---|---|---|
| `BOOT_SAFE` | 初始化中 | 四路为 0 |
| `STOPPED` | 正常待机 | 四路为 0 |
| `RAMPING` | 向目标速度渐变 | 按斜坡更新 |
| `RUNNING` | 已接近目标 | 维持并继续微调 |
| `REVERSING_WAIT` | 准备反向 | 先到 0，再等待 |
| `FAILSAFE` | 心跳、连接或内部故障 | 四路立即为 0 |
| `LOW_BATTERY_LOCK` | 电压过低锁定 | 四路立即为 0 |

状态关系：

```text
BOOT_SAFE → STOPPED → RAMPING → RUNNING
                    ↘ REVERSING_WAIT → RAMPING
任意运动状态 ──超时/掉线/故障──> FAILSAFE → STOPPED
任意状态 ──持续低电压──> LOW_BATTERY_LOCK
```

#### 3.8.2 固定周期更新

- 电机控制周期为 10ms，即 100Hz；
- 网络回调只更新“目标值”，不直接写电机 GPIO；
- 电机任务每次只前进一步，禁止使用长时间 `delay()`；
- 加速默认从 0 到满量程约 500ms；
- 普通减速默认从满量程到 0 约 300ms；
- 换向必须先降到 0，再保持 60ms 死区，然后向反方向加速；
- 参数可标定，但不得把换向死区设为 0。

#### 3.8.3 PWM 输出规则

每个电机只允许一侧输入 PWM，另一侧必须为低电平：

| 轮子命令 | 正向输入 | 反向输入 |
|---|---:|---:|
| 正转 | PWM | 0 |
| 反转 | 0 | PWM |
| 停止 | 0 | 0 |

输出写入采用“先清零旧方向，再设置新方向”的顺序。若发现同一电机两个输入同时出现非零值，安全模块立即清零四路并记录 `MOTOR_FAULT`。

#### 3.8.4 低速启动处理

12V N20 电机使用 5V 供电，最低启动占空比只能实测。每个方向保存：

- `startDuty`：静止时能够可靠起步的最小占空比；
- `runDuty`：转起来后能够持续运行的最小占空比；
- `maxDuty`：电源测试后允许的最大占空比；
- `kickMs`：需要时使用的短启动时间，建议先从 80–120ms 测试。

小于控制死区的指令保持停车。有效起步先按斜坡升至 `startDuty`，确认运动趋势后再落到目标运行值。未完成电流和温升测试前，`maxDuty` 初始建议限制在 70%，通过总装测试后再决定是否开放 100%。

### 3.9 电机标定流程

标定时把车轮架空，随后再落地复核：

1. 单独测试左轮正转，从 0 每次增加 5/255，记录首次可靠起步值；
2. 电机转动后逐步降低，记录能持续运行的最低值；
3. 对左轮反转、右轮正转和右轮反转重复以上过程；
4. 检查 30%、50%、70% 输出时的电流、5V 总线最低电压和温升；
5. 落地直行 1 米，重复 5 次，调节 `leftScale/rightScale`；
6. 低、中、高三档分别做左转、右转和原地转向；
7. 连续做 20 次前后换向，确认每次都先停车且无主控重启；
8. 保存参数并断电重启，复测参数是否生效。

建议保存字段：

```text
leftForwardStart, leftForwardRun, leftReverseStart, leftReverseRun
rightForwardStart, rightForwardRun, rightReverseStart, rightReverseRun
leftScale, rightScale, leftInvert, rightInvert
maxDuty, accelRate, decelRate, reverseDeadMs
```

所有数值要设置安全范围。NVS 读取到非法值时，固件回退到保守默认值，不允许直接带入 PWM。

### 3.10 电池电压检测

硬件分压为 100kΩ/100kΩ，初始公式：

```text
VBAT = VADC × 2 × calibrationFactor + calibrationOffset
```

建议采样策略：

- GPIO3 使用 ADC1，避免与 Wi-Fi 资源冲突；
- 每 500ms 采样一组，共 32 次；
- 去掉最高 4 个和最低 4 个值后求平均；
- 再做指数平滑，建议系数 0.2；
- 页面同时保留原始电压和滤波电压的调试查看入口；
- 使用万用表在高、低两个电压点做标定，目标误差不超过 ±0.10V。

初始阈值只用于开发：

| 状态 | 暂定条件 | 动作 |
|---|---|---|
| 正常 | ≥3.50V | 正常显示和运行 |
| 低电量 | <3.50V 持续 5 秒 | OLED/前灯/网页黄色提醒，降低最大输出 |
| 临界低电量 | <3.25V 持续 3 秒 | 进入 `LOW_BATTERY_LOCK`，停车并红灯提示 |

电机启动产生的短时压降不应立即触发锁定。最终阈值必须根据这节 CR123A 电池的保护特性、万用表读数和带载曲线修改。进入低电量锁定后，只有电压恢复、用户明确解锁或重新上电才允许再次领取控制权。

### 3.11 OLED 与前灯

#### OLED 页面

| 状态 | 显示内容 |
|---|---|
| 启动 | Logo、固件版本、自检进度 |
| 配网 | `AI-Car-XXXX`、`192.168.4.1` |
| 已连接 | IP、Wi-Fi 信号、电池电压 |
| 待机 | 眼睛表情、控制权状态 |
| 行驶 | 方向、档位、左右轮百分比 |
| 低电量 | 电池图标和电压警告 |
| 故障 | 错误码和简短处理提示 |

OLED 刷新频率控制在 5–10Hz，运动控制任务不能等待屏幕完成动画。

#### 前灯规则

| 状态 | 灯光 |
|---|---|
| 启动 | 蓝色缓慢呼吸 |
| 等待配网 | 蓝色闪烁 |
| 已连接待机 | 白色低亮 |
| 前进/后退 | 白色稳定 |
| 转向 | 转向侧黄色闪烁 |
| 低电量 | 黄色慢闪 |
| 急停/故障 | 红色快闪或常亮 |

亮度默认上限建议 20%，避免两颗灯造成明显电源冲击。灯光动画用时间戳推进，不使用阻塞延时。

### 3.12 设置保存与恢复

NVS 建议划分两个命名空间：

- `netcfg`：Wi-Fi 账号、设备名；
- `carcfg`：电机标定、电池校准、安全参数。

每组配置带 `schemaVersion` 和校验字段。保存采用“先校验、再写入、回读确认”的流程。参数修改成功后回传 `ack`；写入失败时保持旧值。恢复出厂设置只能在停车状态执行，并清除网络和标定参数，重启后回到 SoftAP。

### 3.13 日志与故障定位

串口日志波特率为 115200，等级分为 `ERROR/WARN/INFO/DEBUG`。正式运行默认 `INFO`，严禁打印 Wi-Fi 密码。关键日志包括：

- 启动原因和复位原因；
- 固件版本、配置版本和文件系统状态；
- Wi-Fi 连接、断开原因和 IP；
- 控制权领取、释放和超时；
- 电机状态变化、急停原因；
- 低电压触发值；
- 看门狗、内存不足和 JSON 拒绝计数。

日志不能在 100Hz 控制循环中持续大量输出，避免串口打印拖慢电机任务。

## 4. 电脑服务关键模块

### 4.1 首版结论

首版没有独立的电脑后台服务。控制页面由小车提供，电脑和手机都以浏览器作为客户端。这样能减少安装、端口和系统兼容问题。

### 4.2 浏览器客户端模块

| 模块 | 输入 | 输出 | 依赖 | 测试重点 |
|---|---|---|---|---|
| 连接管理 | 小车地址、WebSocket 事件 | 在线/离线状态、自动重连 | 浏览器 WebSocket | 断网、切后台、重连 |
| 控制权管理 | 领取/释放操作 | owner 状态、按钮可用性 | 控制协议 V1 | 两台设备争用 |
| 摇杆与按钮 | 指针、键盘、触摸 | throttle/steering | Pointer Events | 松手必停、多点触控 |
| 安全交互 | 失焦、隐藏、断开 | stop 指令和界面锁定 | Page Visibility | 切应用、锁屏、刷新 |
| 状态面板 | state 消息 | 电量、档位、轮速、故障 | JSON 协议 | 字段缺失和旧消息 |
| 配置页面 | 用户输入 | 校准参数更新 | HTTP/WebSocket | 范围检查、回读确认 |

### 4.3 控制界面

首版页面包含：

- 明显的连接状态和控制权状态；
- 大号急停按钮，始终固定在可触达位置；
- 前进、后退、左转、右转、原地转向按钮；
- 手机虚拟摇杆和电脑方向键/WASD；
- 低、中、高三档速度；
- 电池电压、低电量、Wi-Fi 信号和当前左右轮输出；
- 配网、标定和故障信息入口。

运动按钮采用“按住才动”的死人开关逻辑。键盘按键松开、鼠标移出、触摸取消、窗口失焦时都必须停车。连接未建立、控制权未获得或存在安全锁定时，所有运动按钮保持禁用。

### 4.4 自动重连规则

- WebSocket 断开后页面立即显示红色离线状态并禁用控制；
- 采用 0.5s、1s、2s、4s 的退避重连，上限 5s；
- 重连成功后只恢复状态查看，不自动恢复上次动作；
- 用户必须重新领取控制权并重新按下按钮；
- 页面刷新和手机从后台返回都按新会话处理。

## 5. 任务与优先级

### 5.1 周期任务

| 任务 | 建议周期 | 优先级 | 超时/异常动作 |
|---|---:|---|---|
| 安全监控 | 5–10ms | 最高 | 发现超时或非法输出立即停车 |
| 电机状态机 | 10ms / 100Hz | 高 | 周期严重超时则停车 |
| WebSocket 处理 | 每次主循环 | 高 | 消息校验失败不执行 |
| HTTP 服务 | 事件驱动 | 中 | 不得阻塞电机循环 |
| 状态广播 | 100ms / 10Hz | 中 | 丢一帧可等待下一帧 |
| OLED | 100–200ms | 低 | 故障时跳过动画 |
| 前灯动画 | 50–100ms | 低 | 降级为固定颜色 |
| 电池采样 | 500ms | 中 | 采样异常时标记未知，持续异常停车 |
| Wi-Fi 重连 | 事件 + 1s 检查 | 中 | 先停车，再重连或开 AP |

首版可使用 Arduino 单循环加 `millis()` 定时器实现。若实测网络或 OLED 明显影响 10ms 电机周期，再把电机安全循环放到独立 FreeRTOS 任务。没有测出问题前不增加多任务复杂度。

### 5.2 主循环约束

- 不使用长时间 `delay()`；
- 不在回调内扫描 Wi-Fi、写大文件或播放长动画；
- 单次 JSON 解析有固定内存上限；
- 每轮都优先运行安全和电机更新；
- 记录电机周期最大抖动，目标为 10ms 周期下最大额外延迟不超过 5ms；
- 空闲时喂看门狗，不能用关闭看门狗掩盖阻塞问题。

## 6. 分阶段交付与验收

### S0：工程和安全底座

交付：PlatformIO 工程、固定引脚、串口日志、四路输出上电清零。  
验收：连续复位 20 次，电机脚始终无有效脉冲；串口以 115200 波特输出启动原因。

### S1：外设驱动

交付：OLED I2C 扫描与显示、两颗前灯、电池 ADC。  
验收：OLED 地址识别正确；两灯顺序正确；电池标定后与万用表误差不超过 ±0.10V。

### S2：单电机和双电机控制

交付：四路 PWM、电机状态机、方向和斜坡。  
验收：左右轮正反转正确；20 次换向都先停后转；无主控重启；记录四组最低启动 PWM。

### S3：网络和控制页面

交付：STA、SoftAP、HTTP 页面、WebSocket 协议 V1。  
验收：电脑和手机都能打开页面；连接失败可进入 `192.168.4.1`；状态回传约 10Hz。

### S4：失控保护

交付：控制权租约、心跳、500ms 超时、页面松手保护。  
验收：拔掉路由器、关闭 Wi-Fi、锁屏、关页面和断开 WebSocket，五种情况都在 500ms 目标内停止有效驱动；重连后不会自动续跑。

### S5：转向标定

交付：差速混控、左右补偿、三档速度、参数保存。  
验收：相同地面和相近电量下，直行和左右转各重复 10 次，方向都正确且没有突然反向；断电后参数保留。

### S6：整机稳定性

交付：OLED/灯光状态、低电量保护、完整故障日志。  
验收：连续遥控 15 分钟，无主控重启、网页失联、电机失控或异常发热；在低电量模拟测试中能够提示并锁定停车。

### 6.1 测试层级

1. **编译检查**：固定依赖后全量编译，警告逐项处理；
2. **本地逻辑测试**：差速混合、数值限制、序号去重、状态转换做自动测试；
3. **桌面台架测试**：不接电机验证 GPIO、WebSocket、心跳和 ADC；
4. **离地实机测试**：接单电机，再接双电机，验证方向、PWM、电流和换向；
5. **落地验收**：在固定地面验证直行、转向、断网停车和连续运行；
6. **用户验收**：用户用自己的电脑和手机完成连接、控制、急停、断网和重新连接。

代码编译成功只代表进入实机测试阶段，不能替代整车验收。

## 9. 开发环境要求

### 9.1 电脑环境

- Windows 10/11；
- Visual Studio Code + PlatformIO；
- 数据线支持 USB 数据传输；
- Chrome 或 Edge 用于电脑端测试；
- 手机浏览器使用 Chrome、Edge 或 Safari 的当前稳定版；
- 串口监视器固定 115200 波特率；
- Git 用于记录每个可运行版本。

### 9.2 初始编译配置原则

- 开发板选择与 Seeed XIAO ESP32-C3 相符的 PlatformIO board；
- Arduino-ESP32 框架和依赖在首次实机通过后固定版本；
- 开启 USB 串口日志；
- 为 LittleFS 预留足够空间；
- 发布构建关闭高频 DEBUG 日志；
- 每次更改核心框架、WebSocket、JSON 或 OLED 库版本，都重新执行 S2、S4、S6。

### 9.3 推荐开发顺序

严格按 `S0 → S1 → S2 → S3 → S4 → S5 → S6` 推进。先把电机安全和单机控制验证清楚，再接入网络遥控。每一阶段都保存测试记录和当前参数，未通过的阶段不能直接跳到整车封装。

## 12. 当前结论

- 软件可以覆盖现有全部硬件，GPIO 与 PWM 资源够用；
- 电脑和手机共用响应式网页，首版不需要独立电脑服务或原生 APP；
- STA 负责日常局域网使用，SoftAP 负责首次配网和无路由器场景；
- 运动控制采用单控制者、100ms 指令、200ms 心跳和 500ms 固件超时；
- 差速混控、左右补偿、斜坡加减速和换向死区共同保证动作稳定；
- 没有编码器时只能实现开环一致性，精确距离和角度不在首版承诺内；
- 低电量阈值、电机最低启动 PWM、最大占空比和左右补偿必须通过实车标定；
