# 小车屏幕表情开发文档

版本：V0.4  
日期：2026-10-23  
关联需求：CAR-F09 OLED状态显示，联动驾驶、失联保护及状态上报。  
当前状态：v0.5.0已写入，屏幕仅保留机器人眼睛；固定电脑工作台与自动发现已通过真机连接检查。完整稳定性验收尚未完成。

## 1. 最新确认与目标

用户最初选择带嘴巴的卡通小脸。实物显示后，用户认为带瞳孔的效果有些恐怖，提供了机器人照片，改为两只实心圆角方眼。**当前以用户提供的机器人方眼为准，去掉瞳孔、嘴巴和脸颊。**

用户已看到眨眼；重新演示前后左右联动后，反馈左右看幅度偏小，要求适当增加，避免太夸张。v0.4.2已将转向最大水平位移从±5像素调至±7像素，增加2像素；待机小动作和眼睛大小保持原值。同时使用对称四舍五入，避免定点插值截断让实际位移少一个像素。

完成标准：方眼风格符合用户参考，方向联动清楚，保持可爱感；屏幕动画不影响现有驾驶和停车保护。画面预览、编译通过、设备状态回报和用户亲眼确认分别记录。

| 实测单帧发送 | v0.4.1约95～106ms，短测中写屏错误数为0 |
| 资源 | 单帧缓冲1024字节；显示任务栈4096字节，短测余量约2.2KB |

## 4. 表情与动作联动

| 状态 | 表现 | 进入与退出 |
| --- | --- | --- |
| 启动 | 闭眼后睁开 | 约1.2秒后按联网情况进入连接中或待机 |
| 连接中 | 小幅左右看 | 尚未联网时保持；不显示失效IP |
| 待机 | 圆角方眼，自然眨眼和小幅目光变化 | 已联网且无更高优先级状态 |
| 前进 | 两眼略睁大 | 有效驾驶前后量为正，转向接近零 |
| 后退 | 两眼稍收小、略向下 | 有效驾驶前后量为负，转向接近零 |
| 左转/左斜向 | 两眼向左平移，轻微高低变化 | 转向量为负；回中后恢复 |
| 右转/右斜向 | 两眼向右平移，轻微高低变化 | 转向量为正；回中后恢复 |
| 普通停车 | 目光归中，恢复待机尺寸 | 电机按原规则先请求停车，显示在后续刷新中恢复 |
| 单电机测试 | 较认真的方眼 | 根据测试模式显示，不猜A/B安装左右 |
| 困倦 | 半闭眼 | 连续60秒没有有效操作且电机已停止 |
| 视觉睡眠 | 闭眼弧线、降低亮度 | 连续90秒闲置；有效操作立即唤醒，网络保持在线 |
| Wi-Fi掉线 | 轻微歪头 | 曾联网后掉线；重连不恢复旧运动 |
| 控制中断 | 短暂疑惑 | 控制连接断开或运动指令超时，约1.5秒后回待机 |
| 急停 | 眼睛睁大 | 持续至主动解锁；不自动起步 |
| 电机故障 | 紧张的眼形 | 最高优先级，普通动画不能覆盖 |

普通网页心跳、状态查询和旁观访问不重置闲置计时。有效驾驶、单电机测试、主动停止、领取控制权及解锁可唤醒。驾驶或测试期间不进入睡眠。

## 5. 优先级与方向来源

优先级从高到低：电机故障 → 急停锁定 → Wi-Fi掉线 → 启动/连接中 → 控制中断提示 → 单电机测试 → 驾驶 → 困倦/睡眠 → 待机。

有效指令通过校验后，先保存校准前的`throttle`和`steering`，再计算电机方向：前进为正、后退为负；右转为正、左转为负。表情读取这份驾驶意图，不根据电机电气输出的正负推测方向。

整车前后互换、A/B左右交换和单电机反向设置不改变表情方向。停车、失联、急停和故障时同步清零驾驶意图。无效参数或无控制权的请求不驱动表情联动。这里显示的是用户指令，车身实际左右仍需安装校准。

## 6. 代码实现与错误隔离

| 文件 | 职责 |
| --- | --- |
| `firmware/main/face_engine.c/.h` | 不依赖ESP-IDF的状态选择、定点插值、眨眼及像素绘制；无外部图片依赖 |
| `firmware/main/face_display.c/.h` | 低优先级单任务写屏，状态读取、刷新节奏、显示健康与失败退避 |
| `firmware/main/motor_bench.c/.h` | 保存有效驾驶意图与互动时间；保留原有PWM和停车规则 |
| `firmware/main/main.c` | 初始化屏幕后启动显示任务；Wi-Fi维护和健康日志保持独立节奏 |
| `firmware/main/web_console.c` | 回报表情、刷新状态、栈余量、复位原因和空闲堆等信息 |
| `firmware/main/console.html` | 屏幕栏显示当前表情及最近刷新是否正常 |

显示任务每约125ms调度；不在I²C传输期间持有电机状态锁，也不通过长时间等待串联动画。单帧遇到首个写屏错误就退出；连续3次失败后每2秒低频重试。恢复后重新绘制当前状态，不回放旧动作。

OLED初始化失败或未检测到时，网页与电机控制继续运行。`oled_detected`只表示已识别；`oled_healthy`、错误数、帧计数及最近成功刷新时间用于判断运行健康。

新增`reset_reason`和`heap_free`回报用于诊断。枚举来自当前ESP-IDF头文件。刷写后值11为USB复位，必须结合运行时间是否重新归零判断后续重启，不能把这个值直接当作运行中发生了异常。

## 8. 尚未查清的重启

v0.4.0首次向前短转时出现USB和Wi-Fi同时断开。用户确认没有操作供电且屏幕仍亮；恢复后运行时间重新计数，确认发生过重启。断开前显示错误数为0，显示任务仍有栈余量，但没有抓到那次复位原因，不能确定是供电、程序或USB相关问题。

v0.4.1加入复位原因回报后，0.35秒检查、方向/单电机/急停回归及四方向各2秒演示均未再次重启。它们说明这些短测通过，不代表已修复那次偶发重启。

保留证据：

- `firmware/face-stability-result.first-reset.json`及同名`.jsonl`：首次约71秒观测及中断。
- `firmware/face-device-test-output.first-reset.log`：首次测试超时。
- `firmware/face-reset-probe.json`：v0.4.1短转及后续运行时间、复位原因。
- `firmware/face-device-test-output.log`：v0.4.1联动、单电机、急停和指令超时检查。
- `firmware/face-demo-output.jsonl`：分项可见演示。

若再次发生，先停车，读取复位原因和启动日志，再区分欠压、程序异常/看门狗和USB复位。没有证据前不更改供电接线或关闭安全保护。

## 12. 纯表情与自动发现（v0.5.0）

按用户最新要求，屏幕删除Wi-Fi信号、SLEEP等文字、异常额外图标及底部IP，只保留眼睛。眨眼、驾驶联动和视觉睡眠继续生效，左右最大位移保持±7像素。网络、IP及详细状态集中放在工作台。

电脑双击项目根目录“打开小车控制台.cmd”，固定打开 http://127.0.0.1:8876/ 。脚本自动启动本机后台，按网卡广播UDP发现请求（37020端口），通过固定设备身份和HTTP状态双重核对匹配这台小车。IP失效后持续重新发现，成功后更新地址；旧控制连接关闭，页面重新连接后需要重新取得控制权，不恢复旧运动。

范围为电脑能访问且允许设备间通信的同一局域网或电脑热点。跨网段、访客隔离、广播被拦截时无法保证发现。固定入口由这台电脑提供，需要本机后台运行；手机可使用工作台显示的实际小车IP访问小车页面。此功能不要求USB连接。

验证记录：主机C绘图/显示隔离检查与摇杆JS回归通过；新增自动发现单元检查3项通过。保存地址故意改成192.0.2.1后，真机UDP发现成功找回192.168.137.135，设备身份一致；经固定入口完成WebSocket握手、取得及释放控制权，未发送运动；不可信Origin返回403。浏览器实际显示v0.5.0、正常屏幕状态及两路0%输出。实际DHCP换IP暂未人为触发，换IP关闭旧通道和保存新地址已通过模拟检查。

本次源码备份：`tmp/before-expression-discovery-20261023/`；验证结果：`firmware/workbench-verification.json`；检查入口：`firmware/tests/test_workbench.py`。先前偶发重启与15分钟稳定性仍按第8、9节继续跟进。
