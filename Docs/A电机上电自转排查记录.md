## 已确认与未确认

- 当前固件源码为v0.3.0，app_main最先将GPIO4/5/20/21置为输出低；电机任务初始目标和输出状态均为静态零值。
- A反向设置仅反转非零目标的符号，零目标反向后仍为零。此代码检查不证明故障时的实际引脚电平或驱动输出正常。
- 当前无法建立网络连接，尝试发送的急停指令未送达，不能视为已通过软件停车。
- 电脑无USB串口COM6，无法读取本次电池启动日志。没有重刷固件、清空配置或重新启动电机。
- 用户已选择断电；本轮没有进行带电机复现，也没有测到3.3V、IN1/IN2或MOTOR-A输出，原因尚未确定。

## 后续验证顺序

前提是用户方便断电隔离电机负载，不能用持续自转代替测试。

1. 读取主控启动/复位原因，确认电池供电下主控是否能正常运行、联网及持续保持停车。
2. 测量主控3.3V与公共地，以及驱动输入IN1/IN2对公共地的电平，区分供电/共地、输入不受控与软件指令。
3. 在明确停车输入成立的条件下检查驱动输出，区分控制端和A路驱动故障。
4. 有实测证据后只修对应环节。通过上电默认不转、急停及断联保护后，再恢复常规电机测试。

用户只需回想刚才上电时指示灯、屏幕和热点是否显示连接，不要求为补充描述再次上电。

- 用户补充：电池经升压模块供电和USB给主控供电两种方式均出现过症状；曾测得IN1/IN2相关3.3V，尚未明确是两脚之间还是分别对地，因此不将读数当作完整电平证据。
- 检测到COM6后仅发送STOP和STATUS，未发任何运动指令。串口返回：固件v0.3.0，wifi=connected，ip=192.168.137.61，oled=present，motor=stopped；另有oled_write=ESP_OK。
- 用户随后表示疑似不小心按到主控B按钮，现已恢复。

- 没有重刷固件、改GPIO或再次启动电机。配置入口按最近串口读到的IP更新为192.168.137.61；后续HTTP复查超时且COM6已消失，没有把该次复查记成通过。
