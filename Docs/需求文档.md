## 1. 产品目标

制作一台双电机差速驱动的桌面 AI 小车。用户可通过电脑或手机连接小车，控制前进、后退、左转、右转和停止。小车正面带一块 OLED 屏幕和两颗 RGB 指示灯，可显示表情、联网状态、运动状态和低电量提示。

首版的重点是“控制可靠、转向可控、断网会停、电源安全”。“AI”在首版主要体现在可扩展的软件接口和表情交互，暂不承诺自主导航、语音对话或视觉识别。

预期最终效果：

- 在桌面、木地板等平整室内表面行驶；
- 电脑和手机都能打开控制界面；
- 按住方向键时运动，松开后及时停止；
- 左右电机可分别调速，用差速完成直行、弧线转向和原地转向；
- Wi-Fi 断开、控制页面关闭或指令超时后，小车自动停车；
- OLED 和前灯能让用户看到小车当前状态；
- 有条件时加入电池电压检测和低电量提醒。

## 2. 用户与场景

### 2.1 目标用户

- 主要用户：项目制作者本人；
- 使用方式：桌面展示、近距离遥控、软硬件学习和后续功能扩展；
- 使用地点：室内，优先保证平整桌面和地面；
- 使用距离：同一房间内，具体距离受 2.4 GHz Wi-Fi 环境影响；
- 使用频率：短时间演示和调试，连续续航时间待电池实测后确定。

### 2.2 基本使用流程

1. 用户拨动实体电源开关，小车上电；
2. OLED 和指示灯显示启动状态；
3. 小车连接已配置的 2.4 GHz Wi-Fi；若连接失败，可进入自身热点配网或直连模式；
4. 用户在电脑或手机上打开控制界面；
5. 用户按住方向按钮或虚拟摇杆，小车按指令运动；
6. 用户松开控制、网络中断或指令超时，小车停车；
7. 用户拨动实体开关关闭整车。

### 2.3 使用限制

- 首版只面向室内平整表面，不承诺越障、防水、户外使用或承载能力；
- ESP32-C3 只支持 2.4 GHz Wi-Fi；
- 已确认使用 12V、60 rpm、236:1 的 N20 电机，并以 5V 电源驱动；由于属于降压使用，续航、实际转速、起步扭矩和最大速度以实测为准；
- 电池最大放电电流、升压模块最大输出电流以及电机堵转电流仍未提供，暂不能承诺连续运行时间；
- 调试阶段使用 USB 给主控供电时，要避免 USB 5V 与整车升压 5V 互相反向供电。

### 3.3 第一版已确认的控制方式

首版采用一个响应式 Web 控制界面，并做成可安装的 PWA：

- 电脑通过浏览器打开，可作为电脑控制端；
- 手机通过浏览器打开，也可“添加到桌面”，使用体验接近普通 APP；
- ESP32-C3 提供页面和 WebSocket 控制通道；
- 同一套界面和协议同时服务电脑与手机，首版开发量较小；
- 后续若确认需要原生 Android、iOS 或 Windows 客户端，可复用同一套控制协议。

网络工作模式建议同时保留：

1. **局域网模式（主要模式）**：ESP32-C3 连接家中 2.4 GHz Wi-Fi，电脑和手机在同一网络中控制；
2. **小车热点模式（配网和备用）**：小车自己建立 Wi-Fi 热点，手机或电脑直连后完成配网或应急控制；
3. **公网远程控制**：首版不启用，避免失控和安全问题。

## 4. 明确不做

以下内容不进入首个可行驶版本：

- 摄像头、视频回传和远程公网驾驶；
- 超声波避障、红外循迹、激光雷达和地图导航；
- 语音识别、大模型对话和自主决策；
- 电机编码器闭环控制；
- 自动充电底座；
- iOS、Android、Windows 三套独立原生客户端；
- 户外、防水、跌落和儿童玩具安全认证；
- 修改并重新发布参考模型的 3D 文件。

以上能力可以后续扩展。若用户确认某项必须进入首版，需要重新评估 GPIO、电源、结构和开发时间。

### 5.3 已锁定的电机与供电路线

用户已确认采用以下路线：

`3.7V CR123A 充电电池 → 机械开关 → 固定 5V 升压模块 → 5V 主电源轨 → XIAO ESP32-C3 + 双路 H 桥 + 两个 12V N20 电机`

设计含义：

- 12V N20 长期以 5V 工作，不追求商品标称的 12V/60 rpm 运行点；
- 低电压通常会降低空载转速、起步扭矩和堵转电流，具体数值没有厂家曲线，必须以实测为准；
- 固件要测出左右电机各自的最低启动 PWM，不能直接假设两台电机参数一致；
- 若 5V 下能够可靠起步且转向满足验收标准，则保留现有电机；
- 若出现无法起步、转向差异过大或升压模块掉压，优先重新评估电源和电机，不能只靠提高 PWM 解决；
- 升压模块是固定电源器件，不需要 GPIO 或软件控制。

### 5.4 驱动板版本预审

ST 官方 L298N 是带独立逻辑电源、使能脚和检测脚的双全桥芯片，典型模块体积较大。截图中的小板只有电源、4 个输入和两路电机输出，芯片封装及板形更符合 MX1508 类迷你双 H 桥。用户补充资料给出的模块参数为：2–10V 供电、1.8–7V 信号输入、单路标称 1.5A、峰值 2.5A，并带过热保护和输入悬空防误动作。

需求阶段按“4 输入双 H 桥”核算 GPIO，每个电机使用两个控制输入，共 4 路 GPIO。控制真值表已经确认：

- MOTOR-A：IN1=PWM、IN2=0 为正转；IN1=0、IN2=PWM 为反转；00 为待机；11 为刹车；
- MOTOR-B：IN3=PWM、IN4=0 为正转；IN3=0、IN4=PWM 为反转；00 为停止；11 为刹车；
- 3.3V 的 XIAO GPIO 高电平处于资料给出的 1.8–7V 信号输入范围内。

硬件文档发布最终接线前，仍需完成以下任一芯片身份确认：

- 拍清楚实物芯片顶面丝印；
- 提供商品详情中的芯片型号、电压范围和真值表；
- 用万用表和限流电源完成模块输入/输出验证。

在芯片身份确认前，下载的 ST L298 规格书只用于排除和对比。实际接线和程序按用户提供的 4 输入模块参数及真值表设计。

## 6. 资源核查与风险

### 6.1 GPIO 预核算

| 功能 | 预计占用 | 接口类型 | 说明 |
| --- | ---: | --- | --- |
| 左电机驱动 | 2 | 数字输出/PWM | 两输入控制方向和调速 |
| 右电机驱动 | 2 | 数字输出/PWM | 两输入控制方向和调速 |
| OLED | 2 | I2C | SCL + SDA |
| 两颗 WS2812B | 1 | 单线数字输出 | DIN 串接 DOUT，两颗灯共用一根数据线 |
| 电池电压检测 | 1 | ADC 输入 | 通过电阻分压读取电池端电压 |
| 合计 | **8** |  | 实体电源开关不占 GPIO |

XIAO ESP32-C3 官方引脚表确认板边引出了 D0–D10，共 11 个 GPIO。建议的低风险预分配如下，最终逐点接线将在硬件文档中定稿：

| XIAO 引脚 | ESP32-C3 GPIO | 预分配功能 | 选择理由 |
| --- | ---: | --- | --- |
| D1 | GPIO3 / ADC1_CH3 | 电池电压检测 | 使用官方建议的 ADC1 引脚，避开 ADC2 采样问题 |
| D2 | GPIO4 | 电机 A：IN1 | 普通数字输出，可输出 PWM |
| D3 | GPIO5 | 电机 A：IN2 | 普通数字输出，可输出 PWM；不用于 ADC |
| D4 | GPIO6 | OLED：SDA | XIAO 默认 I2C 数据脚 |
| D5 | GPIO7 | OLED：SCL | XIAO 默认 I2C 时钟脚 |
| D6 | GPIO21 | 电机 B：IN3 | 普通数字输出，可输出 PWM |
| D7 | GPIO20 | 电机 B：IN4 | 普通数字输出，可输出 PWM |
| D10 | GPIO10 | 两颗 WS2812B 的 DIN | 普通数字输出，避开启动配置脚 |
| D0 | GPIO2 | 暂不使用 | 启动配置脚，保持空闲更稳妥 |
| D8 | GPIO8 | 暂不使用 | 启动配置脚，保持空闲更稳妥 |
| D9 | GPIO9 / BOOT | 暂不使用 | 启动/下载相关引脚，保持空闲 |

电机 PWM 需要 4 路输出能力，ESP32-C3 最多提供 6 路 LED PWM 通道，数量够用。

**预审结论：GPIO 刚好够完成全部首版功能，电池检测可以保留。使用 8 路后还剩 D0、D8、D9 三个物理引脚，但三者都是启动配置相关引脚，因此首版没有低风险的普通 GPIO 余量。后续 I2C 传感器可以继续挂在 D4/D5 上共享总线。**

### 6.2 电源资源预审

规划中的电源链为：

`3.7V CR123A 电池 → 实体开关 → 固定升压模块 → 5V 主电源轨 → 电机驱动和外设；5V 主电源轨 → 串联肖特基二极管 → XIAO ESP32-C3 的 5V 引脚`

Seeed 官方说明允许从 XIAO 的 5V 引脚输入电源，但要求外部电源与 5V 引脚之间串联二极管。二极管方向为：升压模块 5V 输出接二极管阳极，二极管阴极接 XIAO 5V 引脚。这样也能降低调试 USB 与外部 5V 互相顶电的风险。

主要风险：

1. 电机启动和堵转电流远高于空载电流，升压模块和电池保护板可能瞬间限流；
2. 电机噪声可能让 5V 电源下跌，造成 ESP32-C3 重启或 Wi-Fi 断开；
3. 电池标称 1850mWh，在 3.7V 下约为 500mAh；截图中的“5V 250mA”是充电输入参数，不能当作电池的放电能力；
4. 双路驱动模块接口参数已提供，但模块芯片身份、实际压降和持续散热能力仍需实测；
5. 两颗裸 WS2812B 需要就近去耦，5V 供电时还要核对 3.3V 数据高电平余量；
6. USB 调试供电和电池升压供电不得未经确认直接并联。

进入实机总装前，至少要确认：电池最大放电电流、升压模块连续/峰值输出、两个电机在 5V 下的空载电流和短时堵转电流。驱动芯片型号仍建议核实，但用户提供的模块参数和真值表已经足够继续绘制接线方案。

### 6.3 运动控制风险

- 两个开环 N20 电机存在转速差，小车可能跑偏；首版用左右 PWM 补偿改善，无法达到编码器闭环的直线精度；
- 快速从正转切到反转会产生电流冲击，固件必须安排减速、短暂停车和反向加速；
- 低占空比下电机可能只响不转，需实测左右电机的最低启动 PWM；
- 履带或轮胎摩擦差异会影响转弯半径，需要在固定地面标定低、中、高三档参数；
- Wi-Fi 指令不能直接无限期保持，必须用心跳和超时停车。

## 7. 预审结论

### 7.1 当前可以确认

- 产品功能和首版范围清楚，可以继续做硬件方案；
- 双电机差速控制、OLED、两颗串联 RGB 灯和电池检测在 ESP32-C3 的功能资源范围内；
- 主控锁定为 XIAO ESP32-C3；首版需要 8 路 GPIO，D1–D7 和 D10 可以覆盖，D0/D8/D9 保留；
- 电池检测可以保留，但首版分配后没有低风险的普通 GPIO 余量；
- 固定升压模块不占 GPIO，电源开关也不占 GPIO；
- 两个 12V、60 rpm、236:1 的 N20 电机锁定为 5V 驱动，性能以实测和软件标定为准；
- 首版确认使用响应式 Web/PWA 同时覆盖电脑和手机，原生 APP 留作后续方向；
- 稳定控制必须包含 PWM 斜坡、换向停顿、心跳超时停车和左右电机补偿；
- 参考模型适合用作外观参考，不能作为电路设计依据。

### 7.2 当前不能确认

- 截图驱动板究竟是 MX1508、同类替代芯片，还是其他型号；
- 单节约 500mAh 的 CR123A 充电电池和现有升压模块能否承受两台电机启动电流；
- 12V N20 在 5V 下能否达到所需起步、转速和转向一致性；
- 实际续航、最高速度、转弯半径和连续运行温升；
- OLED 模块和 WS2812B 实物版本的准确供电范围。

### 7.3 进入下一阶段的条件

用户确认以下方向后，再输出《硬件技术文档》：

1. 补充升压模块正反面照片或连续/峰值输出电流参数；
2. 条件允许时补充驱动板芯片丝印近照；
3. 实物到手后测量结构尺寸，并测试两台电机在 5V 下的空载电流、最低启动 PWM 和短时堵转电流。

硬件文档完成后，将给出：完整电源路径、逐点接线表、最终 GPIO 分配、滤波与保护、首次上电步骤及单模块测试方法。随后再输出软件技术文档，详细说明 Wi-Fi 配网、WebSocket 协议、电机状态机、速度斜坡、转向标定、失联保护和测试方法。
